# Deploy to IIS (Windows)

The deployment package is a framework-dependent `win-x64` publish of the ASP.NET Core app, including the built React UI and this runbook. It does not contain a database, imported school data, generated PDFs, or credentials. IIS can use its default environment; no environment setting or separate production configuration file is needed.

## 1. Build the package

On a Windows build machine, install the .NET 8 SDK and Node.js/npm, then run from the repository root:

```powershell
.\scripts\New-IisDeploymentPackage.ps1
```

The package is written to `artifacts\iis-deployment.zip`. To choose another location:

```powershell
.\scripts\New-IisDeploymentPackage.ps1 -OutputPath 'C:\deploy\iis-deployment.zip'
```

## 2. Prepare the IIS server

1. Install the IIS Web Server role and the **.NET 8 Hosting Bundle** on a supported Windows Server. The hosting bundle installs the ASP.NET Core Module required by IIS. Restart IIS after installing it.
2. Extract the ZIP to an application directory, for example `C:\inetpub\AccessibleSchoolReports`.
3. Create the persistent data directory and grant the site's application-pool identity Modify access:

   ```powershell
   $appPool = 'AccessibleSchoolReports'
   $dataRoot = 'C:\ProgramData\AccessibleSchoolReports'
   New-Item -ItemType Directory -Force -Path $dataRoot | Out-Null
   icacls $dataRoot /grant "IIS AppPool\$appPool`:(OI)(CI)M" /T
   ```

   The app connects to `C:\ProgramData\AccessibleSchoolReports\data\schoolreports.db` and stores PDFs in `C:\ProgramData\AccessibleSchoolReports\output`. The app creates the database file and applies migrations on startup. Keep these folders when replacing the published app, and back them up.
4. In IIS Manager, create an application pool with **.NET CLR Version: No Managed Code** and **Managed pipeline mode: Integrated**. Create a website pointing to the extracted directory and select that pool.
5. Configure an HTTPS binding with a valid certificate. Do not expose the site over plain HTTP; the app redirects HTTP to HTTPS.
6. Verify the deployed `web.config` exists in the site root. It is generated by `dotnet publish`; do not replace it with a classic ASP.NET Framework configuration.

## 3. Sign in

No Development/Production setting is needed. The application uses the same root `appsettings.json` in every environment and connects to the persistent SQLite file above. If your existing database is in a different folder, change only `ConnectionStrings:SchoolReports` in this file to its full path. If that database already contains your Identity users, use the existing username and password; you do not need to configure seed credentials. Do not replace the database with a new empty file if you need its existing accounts and data.

For a new, empty database only, create its first Admin account by setting the `Identity` values in the deployed `appsettings.json`. Use a password with at least 8 characters, including upper and lower case, a digit, and a non-alphanumeric character:

```json
"Identity": {
  "SeedUserName": "your-admin-name",
  "SeedPassword": "Your-Strong-Password-1!",
  "SeedRole": "Admin"
}
```

Start the site. Startup creates the account or resets and unlocks that username in the configured database. Sign in with those values, then stop the site and clear all three seed settings. While present, the configured password is applied at every startup. Do not leave a seed password in the deployed settings file.

The app runs EF Core migrations and ensures its roles at startup. Resetting the account through these seed settings also clears its failed-sign-in lockout. Authentication is intentionally retained; the application does not ship with a shared default admin password.

## 4. Configure OpenAI

The package defaults to OpenAI-compatible embeddings (`text-embedding-3-small`, 1536 dimensions) and chat (`gpt-4o-mini`). If your current key/provider settings are in an old `appsettings.Production.json`, copy the OpenAI values into the root `appsettings.json`; the app deliberately ignores environment-specific JSON files. Enter your OpenAI API key in both existing fields:

```json
"Embeddings": {
  "ApiKey": "your-openai-api-key"
},
"LanguageModel": {
  "ApiKey": "your-openai-api-key"
}
```

Keep the other settings already in the file. The key stays server-side; never put it in `wwwroot` or commit it to source control. Restrict access to the settings file to Administrators and the IIS app-pool identity, then restart the IIS site.

Startup re-embeds existing chunks when their stored provider/model differs from the configured OpenAI model. The configured embedding dimensions must match the OpenAI model's response.

## 5. Verify and back up

- Browse to the HTTPS site URL and sign in as the administrator.
- Import a workbook, generate a report, and download the resulting PDF.
- Back up `C:\ProgramData\AccessibleSchoolReports` regularly. Keep a single IIS instance pointed at a given SQLite file; do not run multiple app instances against it.
- For upgrades, stop the site and replace the application files; retain the ProgramData database and output folders. The app intentionally ignores `appsettings.Development.json` and `appsettings.Production.json`, so the root `appsettings.json` is the single settings file.
- The SPA HTML is sent with no-cache headers. Each publish cleans out obsolete hashed bundles and includes exactly the assets referenced by its `wwwroot\index.html`. After upgrading, restart the site and hard-refresh the browser once.

If startup fails, check Windows Event Viewer and the IIS/ASP.NET Core Module logs. Enable ANCM stdout logging only temporarily for diagnosis, secure the log directory, and disable it again afterward.
