Problem

A reporting shop trapped in SAS

Two SAS 9.4 programs plus an Excel extract preprocess graduate rows, compute counts and salaries, and emit one PDF per school.

  • SAS must be installed and pointed at local paths.
  • Rules live in DATA / PROC steps, not automated tests.
  • ODS PDF (STYLE=GrayscalePrinter) is a print layout.
  • Only the first school’s ods pdf used the accessible option.

What “done” is not

The preserved baseline PDF is a Test University artifact. It is useful for layout and value mapping. It is not an accessibility certificate, and it is not the same population as the sample Excel workbook.

Constraints

What we refused to do

Do not invent rules

Characterize SAS first. Document ambiguity. Eighteen skipped tests stay skipped.

Do not restyle the PDF

Keep seven letter pages, gray headers, black grid, SAS titles. Tags go behind that design.

Do not switch databases

SQLite is the required MVP store. No SQL Server, no vector database.

Do not claim accessibility

Target tagged PDF / PDF-UA and WCAG 2.2 AA principles. Report validation separately.

Method

Characterize before implement

Legacy SAS
    → Rule ID (CF-* / SS-*)
    → docs/capstone/business-rules.md
    → C# (LegacyRecodes, calculator, layout)
    → Characterization + unit test
    → Generated report

Ambiguous SAS is recorded as skipped tests, not guessed values. Change protocol: list files, rules, tests, and risks before behavior changes. Human approval is required for major rule changes.

Import

Excel graduate workbooks

  • Accepts .xlsx only (UI maximum 10 MB).
  • Validates required columns; records invalid and blank rows.
  • Rejects a duplicate file content hash.
  • Persists optional class year for dashboard analytics.
  • Admin-only page: /import.

Dashboard counts

Live school and graduate headcounts come from stored import rows. Duplicate re-uploads do not change those numbers. They are not printed report totals.

Generation

One school or all schools

Single

Pick a stored school and year. Write one seven-page letter PDF.

Sequential all

One run, one school after another. History stores duration.

Bounded parallel

Max 1–8. Per-school isolation. Text compare, not a required speedup.

No formal 189-school benchmark is in the repo. If a timing is needed, copy duration from Run History. Do not invent timings.

PDF

Visual parity first, tags behind it

Preserve

  • Seven letter pages, one table per page
  • Centered bold italic school name and title
  • Gray headers, black grid, 8pt body / 9pt headers
  • Total Reported as a table row on page 1
  • Note, then test-client footer, in content flow

Adobe Acrobat check

  • Presenter-run accessibility checker passed
  • Screen / reading order is correct
  • Recorded separately from generation
  • Not a veraPDF, PAC, or NVDA pack
  • Do not restyle the page or invent association names

Security

Authentication

ASP.NET Core Identity
    → cookie .asr.auth (HttpOnly, SameSite Lax, Secure on HTTPS)
    → roles Admin / ReportUser / Viewer
    → AppPolicies
    → UserSchoolAccess
    → IReportAuthorizationService

POST /account/signin with antiforgery. Local returnUrl only. Seed credentials are empty in committed config.

Security

School grants and downloads

PolicySurfaces
RequireAdminImport, Generate all
RequireReportGenerationGenerate one
RequireReportAccessDashboard, history, PDF
RequireRagAccessAssistant

PDF access

Files are under configured OutputRoot, not wwwroot. Load by integer id, check CanViewReportAsync, confine the path, return the file or 404. Path traversal is tested and denied.

Assistant

Knowledge Assistant is not the calculator

Catalog (SAS + listed markdown) + generated PDFs the user can view
    → chunk (Rule IDs when present)
    → lexical embeddings by default
    → authorization-aware retrieval
    → grounded prompt (retrieved text is untrusted data)
    → optional chat completion
    → cited answer, or Insufficient evidence

Excel graduate rows are never indexed. Printed-value questions quote the PDF. Sums and year differences use printed figures, not a SAS rerun.

Assistant

RAG security

  • Filter documents with KnowledgeAccess before scoring.
  • Report-scoped Ask: that PDF only; catalog excluded.
  • Unauthorized ?report= → “That report is not available.”
  • Prompt-injection text is data, not instructions.
  • Keys stay in user secrets. Timeouts and retries on the chat API.
