# Speaker notes — prototype showcase

Present the `.pptx` in Slide Show (**F5**). Speak the headline. Use these lines only if you stall.

## 1. Hook

“School employment reports still start with two SAS programs and a shared folder.” Pause. “We turned that into a signed-in product — without inventing a rule.”

## 2. Name

“Meridian Test Client. Import. Generate the same seven-page PDF. Download only what you are allowed. Ask from authorized evidence.”

## 3. Customer

A reporting shop. Excel in. One Class of 2025 PDF per school out. They cannot break suppression, recodes, or who sees which file.

## 4. Old way

Install SAS. Point at folders. Run two programs. Collect print PDFs. Email. No sign-in.

## 5. Cost

If only one person can run SAS, the shop cannot scale or prove a cycle. No history. No test on n < 5. No 404.

## 6. Pitch

Same SAS rules. A product instead of a ritual. Keep / add / refuse.

## 7. How it works

Six beats. Totals stay in the calculator. The assistant is last, not first.

## 8. The report

We did not redesign it. Adobe checker passed; reading order correct. Not veraPDF/PAC/NVDA.

## 9. Trust

Admin / report user / viewer / no grant. Wrong id is 404.

## 10. Assistant

Quotes printed PDFs. Can sum printed Total Reported. Never reruns SAS. Insufficient evidence is a feature.

## 11. Unfair advantage

Characterize first. CF-S-00. AI wanted salaries when n < 5. Humans said no.

## 12. Traction

Live app. Tests. Adobe. CI. Authz. Honest miss on baseline population.

## 13. Why not SAS

SAS knows the rules. It is not a product.

## 14. Live demo

Switch to the browser. Follow `DEMO-SCRIPT.md`. Do not generate all schools.

## 15. Fine print

Say the no’s out loud. Investors trust that more than a certificate you do not have.

## 16. Ask

Green-light the prototype. Hold the rules. Judge preservation and access, not a restyle.

## 17. Close

“The reports did not change. The shop finally can.” Then take questions.
